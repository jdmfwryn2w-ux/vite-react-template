# AGENTS.md

This file provides guidance to AI coding agents working in this repository.

## Project Overview

A full-stack template combining a React + Vite frontend with a Hono backend, all deployed as a single Cloudflare Worker. The frontend is an SPA served as static assets, while API routes are handled by a Hono app in the Worker entry. Built with the `@cloudflare/vite-plugin` so Vite builds both the client and the Worker.

This is a **template** repository (part of `cloudflare/templates`), meant to be copied and customized.

## Tech Stack

- **Frontend:** React 19 + Vite 7, with `@vitejs/plugin-react`
- **Backend:** Hono 4 (API routes in the Worker entry)
- **Platform:** Cloudflare Workers, deployed via `@cloudflare/vite-plugin` + Wrangler
- **Language:** TypeScript (strict, multi-project `tsconfig` setup)
- **Linting:** ESLint 9 flat config (`eslint.config.js`) with `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`
- **Runtime:** `nodejs_compat` compatibility flag

## Project Structure

```
vite.config.ts                 Vite + React + Cloudflare plugin config
wrangler.json                  Worker config: main entry, assets, observability
eslint.config.js               ESLint flat config
index.html                     SPA entry HTML (loads src/react-app/main.tsx)
tsconfig.json                  Solution/config that references app + node + worker
tsconfig.app.json              TS config for the React app
tsconfig.worker.json           TS config for the Worker
tsconfig.node.json             TS config for Node tooling (vite.config etc.)
src/
  worker/index.ts              Worker entry — Hono app, exports `default`
  react-app/                   React SPA
    main.tsx                   React entry point
    App.tsx                    Root component (fetches /api/)
    index.css, App.css         Styles
    vite-env.d.ts              Vite client types
    assets/                    SVG logos (react, hono, cloudflare)
worker-configuration.d.ts      Generated Cloudflare bindings types (do not edit by hand)
```

## Common Commands

All commands run from the repository root.

| Command | Action |
| --- | --- |
| `npm install` | Install dependencies |
| `npm run dev` | Start Vite dev server with HMR at `localhost:5173` |
| `npm run build` | Type-check (`tsc -b`) and build for production (`vite build`) |
| `npm run preview` | `npm run build && vite preview` (preview the production build) |
| `npm run lint` | Run ESLint (`eslint .`) |
| `npm run check` | Full check: `tsc && vite build && wrangler deploy --dry-run` |
| `npm run deploy` | Deploy to Cloudflare Workers (`wrangler deploy`) |
| `npm run cf-typegen` | Regenerate `worker-configuration.d.ts` from Wrangler config |
| `npx wrangler tail` | View real-time logs from deployed Worker |

## Conventions & Notes

- **API routes:** Add backend endpoints in `src/worker/index.ts` (the Hono app). The example route is `app.get("/api/", ...)` returning `{ name: "Cloudflare" }`. The React app calls this from `App.tsx`.
- **Worker entry:** `wrangler.json` sets `main: "./src/worker/index.ts"` and serves the built SPA from `./dist/client` with `single-page-application` not-found handling.
- **Build pipeline:** `npm run build` runs `tsc -b` (builds all referenced tsconfigs) followed by `vite build`. Always run `npm run build` before `npm run deploy` (or use `npm run build && npm run deploy`).
- **TypeScript project references:** The repo uses a solution-style `tsconfig.json` referencing `tsconfig.app.json`, `tsconfig.worker.json`, and `tsconfig.node.json`. Type errors surface during `tsc -b` in the build step.
- **Generated files:** `worker-configuration.d.ts` is generated by `wrangler types` — run `npm run cf-typegen` to regenerate, do not edit by hand. `dist/` is a build artifact and is gitignored.
- **Observability** is enabled in `wrangler.json`; source maps are uploaded.
- **Env bindings:** New Cloudflare bindings (KV, D1, R2, vars, etc.) should be declared in `wrangler.json` and typed via the regenerated `worker-configuration.d.ts` (the `Env` interface). The Hono app is typed as `Hono<{ Bindings: Env }>`.
